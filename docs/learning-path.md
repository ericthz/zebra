# Zebra 学习路径（技能 → 原理 → 小练习）

> 目的：不按目录平推，而是按"技能 → 代码入口 → 亲手改一处代码观察行为"的方式
> 掌握 AI Agent 原理。每关都是"读讲义（文件头注释）→ 跑测试 → 改一处代码 → 看它怎么崩 / 怎么变"。
> 全程约 3~6 小时（取决于你停在哪一关做实验）。
>
> 配套材料：README §2 原理地图（技能点 → 代码入口）、README §8 路线图（P0~P63，
> 每个里程碑对应一个 `git show <commit>` 从零到一的提交）。

## 前置

```bash
# 0. 跑起来再说（有模型就看行为，没模型也能看单测）
ollama pull qwen3.5:0.8b-mlx   # 或任意支持 tool calling 的本地模型
go run ./cmd/zebra             # 输入：北京天气怎么样？
```

## 第一关：工具调用循环 —— Agent 的最小骨架

**入口**：`internal/agent/agent.go` 文件头注释 + `toolLoop`。

**原理**：模型返回工具请求 → 执行工具 → 结果回填 → 再调模型，直到输出纯文本。
这是 Agent 区别于"聊天机器人"的分水岭。

**练习**：
1. 跑 `go test ./internal/agent/ -run TestToolLoop -v`，观察多少次往返才回答。
2. 改：把 `agent.go` 里 `MaxTurns` 默认值改成 1，重跑测试，看"工具没执行完就截断"的报错。
3. 改回，再故意让工具返回一个错误（`tool/builtin.go` 计算器除零），看参数纠错重试怎么被触发。

**验收**：你能说出"一次对话中，模型和工具各被调用了几次，为什么"。

## 第二关：上下文工程 —— 为什么长对话不崩

**入口**：`internal/agent/context.go`（token 估算 + 滑动窗口）、`internal/agent/summarize.go`（摘要压缩）。

**原理**：上下文窗口有限，不能无限堆历史。超限策略是"裁剪最旧的 + 摘要保留语义"。

**练习**：
1. `internal/agent/context_test.go` 找测试，看窗口裁剪边界。
2. 改：把 `ContextWindow.MaxTokens` 调成 200，用 CLI 连续聊 5 轮，观察"旧内容被压缩成摘要"的日志。
3. 回答：为什么摘要在 system 提示里、而不在 user 消息里？（提示：看 buildMessages 的拼接顺序）

---

## 第三关：规划-执行 vs ReAct —— 两种"想清楚再做"

**入口**：`internal/agent/plan.go`、`internal/agent/react.go`。

**原理**：plan 先把任务拆成步骤（结构化 JSON）再逐步执行；react 是边想边做
（思考→行动→观察 三元组）。一个适合长任务编排，一个适合单步推理链。

**练习**：
1. CLI 切 `plan` 模式：`/mode plan` 然后问一个多步任务，观察"先出计划再执行"。
2. 切 `react` 模式重复同一问题，对比轨迹差异。
3. 读 `plan.go` 的 `executeStep`：为什么子步骤"不写历史"？（防污染召回，答案在注释里）

---

## 第四关：反思与自一致性 —— 让模型自己检查自己

**入口**：`internal/agent/reflect.go`。

**原理**：反思 = 生成答案后让模型批判再改进（失败回退原文）；自一致性 = 独立采样
多份回答再择优（降随机性）。这是"质量闭环"在单 Agent 内的最小形态。

**练习**：
1. 跑 `TestSelfConsistent*` 测试，看采样次数与择优逻辑。
2. 改：把 `SelfConsistent` 的采样数从 3 改 1，跑同样测试，对比"自一致性到底带来什么"。
3. 想想：反思和自一致性哪个更贵、哪个更稳？为什么（看各自的降级路径）。

---

## 第五关：多 Agent —— Supervisor 路由与辩论

**入口**：`internal/supervisor/`（路由）、`internal/agent/debate.go`（辩论）。

**原理**：supervisor = 一个"老板"模型决定任务派给哪个专业 worker（LLM 路由 +
关键词兜底）；debate = 双立场独立作答 → 交换观点 → 评审选优。

**练习**：
1. CLI `/mode supervisor`，分别问天气类 / 计算类问题，观察路由到不同 worker。
2. `/mode debate` 问一个有争议问题，看"双观点 + 评审"的完整轨迹。
3. 改：给 supervisor 的 `keywordRouter`（`internal/supervisor/`）加一个关键词规则，
   跑对应测试看路由变化。

---

## 第六关：记忆 —— 分层、画像、遗忘

**入口**：`internal/memory/`（工作记忆 + 长期记忆）、`profile.go`（画像）、`forget.go`（遗忘）。

**原理**：工作记忆管会话内，长期记忆跨会话（向量/Redis）。画像从对话抽取事实按置信度合并；
遗忘 = TTL + 容量裁剪 + 被遗忘权。只进不出的记忆是缺陷。

**练习**：
1. CLI 里告诉它"我叫张三，在北京"，开新会话再问"我叫什么"——观察长期记忆检索。
2. 跑 `forget_test.go`，看 TTL 过期后记忆如何消失。
3. 改：把工作记忆容量（`NewWorkingMemory(10)`）改成 2，连续聊 5 句，看"最旧被挤掉"。
   然后问：为什么挤掉的是最旧的而不是最不相关的？（提示：这是简化设计，生产用重要性排序）

---

## 第七关：知识库 RAG —— 检索、混合、重排、引用

**入口**：`internal/rag/`（分块 + BM25/向量混合 + 重排）、`internal/agent/agent.go`（引用注入）。

**原理**：文档 → 分块 → 嵌入 → 检索 → 重排 → 带【来源】注入，回答可溯源、防幻觉。
BM25 补向量召回、重排补相关性，是"检索质量三件套"。

**练习**：
1. `docs/` 放一篇文档，CLI 问文档内容，观察命中片段带【来源】标记。
2. 跑 `rag` 包测试，看 BM25 与向量分数如何 z-score 融合。
3. 改：把 `rerank.go` 的 topK 调小，问一个需要长上下文的问题，观察"召回不足"的现象。
   再改：把引用注入的 `<来源>` 标记改成无标记，问模型"你怎么知道的"——对比幻觉倾向。

## 第八关：评测 —— 让模型给模型打分

**入口**：`internal/eval/judge.go`（Judge）、`test/eval/`（golden / redteam 用例集）。

**原理**：LLM-as-Judge = 用评审模型对回答打"忠实/相关/安全"三维分；golden 集回归防能力退化；
红队集防注入越狱。这是"上线前换模型 / 改 prompt"的底线。

**练习**：
1. 跑 `ZEBRA_EVAL=1 go test ./test/eval/ -run TestGoldenEval -v`，看真实模型能不能调对工具。
2. 换模型（`OLLAMA_MODEL`）对比得分——你会立刻看到"小模型与大模型的工具调用差距"。
3. 改：往 `test/eval/cases/redteam.json` 加一条越狱用例，跑红队看安全分门槛是否拦下。
4. 读 `judge.go` 打分规则注释：为什么"拒绝危险请求"给高分、只有实际泄露才低分？

## 第九关：安全 —— 注入、脱敏、SSRF、审计

**入口**：`internal/safety/`（注入防护 + 审核 + 脱敏 + SSRF）、`internal/tool/registry.go`（审计 + 二次确认）。

**原理**：Agent 对外要防 Prompt 注入（工具结果隔离 + 特征检测）、对内要防数据泄漏
（日志强制 Redact）、对目标系统要防 SSRF（协议/内网/域名白名单）。高危工具人工确认 + 全量审计。

**练习**：
1. 跑 `safety` 包测试，看注入特征如何被识别。
2. 改：在日志里打印 `API Key` 字段，跑测试看 `Redact` 怎么把它掩码（`safety_test.go`）。
3. 用 CLI 触发 `FetchTool` 访问内网地址，观察 SSRF 白名单拦截（`ssrf_test.go`）。

---

## 第十关：规模化 —— 异步任务与 Redis

**入口**：`internal/task/`（状态机 + 消费者队列 + 检查点）、`internal/redis/`（手写 RESP 客户端）。

**原理**：长任务不能阻塞 HTTP，要用"任务队列 + 状态机 + 检查点恢复"；多实例共享
会话/任务/记忆需要外部存储（这里用纯标准库手写 RESP 客户端，展示协议原理）。

**练习**：
1. 跑 `task` 包测试，看检查点如何实现"断点续跑"。
2. 跑 `redis` 包测试，读 RESP 客户端代码，看它如何解析 `+OK\r\n` / `$len\r\n...`。
3. 回答：为什么"把会话迁到 Redis"就能水平扩展？（提示：看 `session.go` 的存储接口）

## 过关之后（消化期，不是加功能期）

学完十关，你已经有能力回答"Agent 是怎么工作的"。接下来建议：

- **换模型重测**：用不同 size 的模型跑第八关评测，建立"模型能力敏感度"直觉；
- **删代码重建**：挑一个包（如 `reflect` 或 `summarize`），注释掉它再跑测试，
  看 Agent 退化成什么样子——"去掉一个技能后系统如何降级"比加技能更值钱；
- **写自己的工具**：仿照 `internal/tool/builtin.go` 写一个工具并注册，端到端体验
  "声明 Schema → 模型选择 → 执行 → 回填"完整链路；
- **读提交史**：`git log --oneline` + `git show <commit>`，看每个技能"从零到一"是
  怎么被加进来的——这是最快的"作者视角"。

> 十关后不要再堆功能。这仓库的终点不是"更多能力"，而是"你能看懂每个能力的
> 权衡与代价"。停在这里，把时间花在 删代码 / 换模型 / 写工具 三个实验上。
