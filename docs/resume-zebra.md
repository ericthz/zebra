### 项目描述

自研的 **AI Agent 框架**：从模型接入到生产灰度切换全自研，零第三方框架依赖（仅 Go 标准库）。覆盖 **Agent 编排、工具调用、多 Agent 协作、上下文工程、分层记忆、RAG、评测闭环** 全链路。代码约 **2.6 万行、192 个 Go 文件（含 87 个测试）、31 个包**，提供 CLI / HTTP / MCP 三种接入方式。

### 项目职责

- 设计并实现 **Agent 核心引擎**：多模型路由与降级、上下文预算裁剪、工具调用循环、六种推理范式（Plan-and-Execute / ReAct / Reflect / Debate / Self-Consistent / Supervisor 多 Agent 路由）
- 设计并实现 **Agent 工具系统**：工具注册表、角色权限白名单、高危二次确认、审计日志、沙箱执行与 SSRF 防护
- 设计并实现 **Agent 记忆与知识**：工作记忆 + 长期记忆（Qdrant/Redis）+ 用户画像与遗忘、RAG 混合检索、知识图谱、技能检索
- 设计并实现 **Agent 评测闭环**：LLM-as-a-judge 三维评分、影子评测灰度切换、红队安全用例、反馈回流自动回归

### 项目业绩

- **从零实现完整 Agent 能力栈（零第三方框架依赖）**：不依赖 LangChain 等任何 Agent/LLM 框架，仅用 Go 标准库实现 Ollama / OpenAI / Anthropic 三模型适配、结构化输出、工具调用、语义缓存、向量检索，证明了对 Agent 底层原理的深入理解与工程落地能力。
- **多 Agent 协作与推理范式**：落地 Supervisor 多 Agent 路由（LLM 选 worker + 关键词兜底）、Plan-and-Execute 三阶段、ReAct 显式推理轨迹、Debate 双人格辩论、Self-Consistent 多数投票，覆盖主流 Agent 编排模式，并实现多工具并行执行（fan-out / fan-in）。
- **修复流式降级 3 处关键缺陷**：流式中断/建立失败时客户端"只收 done 不收回答"、重复播报等，实现"已播内容不重复、剩余内容自动补全"的降级链路并配套回归测试。
- **搭建评测闭环**：LLM-as-a-judge 三维评测（忠实/相关/安全）+ 影子评测灰度切换 + 红队安全用例，修复工具调用检测、超时、Judge 语义误判等 4 处评测基建问题，使评测在本地 4B 模型上稳定通过（golden 4/4、红队 5/5），沉淀为可回归的自动化评测集。
- **AI Agent 指标实测**：评测集工具调用与回答正确率 4/4（100%），红队安全用例（注入/越狱/数据外泄）5/5 全部安全拒绝（100%），Judge 三维评分（忠实/相关/安全）阈值 0.7 达标。
- **工程指标**：87 个测试文件、287 个测试函数、约 2.6 万行代码全量 `go test`、`go vet`、`-race` 竞态检测通过，零第三方依赖。
- **工程质量**：全量 `go test`、`go vet`、`-race` 竞态检测通过；沉淀 `technical-summary.md`、`learning-path.md` 技术文档与十关学习路径，覆盖 Agent 技术难点与生产演化方向。

## 五、附：AI Agent 岗位面试常被追问的方向（参考技术总结）

- **Agent 编排**：ReAct 与 function-calling 工具循环的区别？Supervisor 路由为什么先 LLM 后关键词兜底？
